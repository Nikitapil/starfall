# Дизайн-система Starfall

## 1. Направление

Starfall — тёмный тактический sci-fi интерфейс. Он должен ощущаться технологичным и атмосферным, но не превращаться в неоновую панель управления. В основе — почти чёрный сине-серый фон, светлые нейтральные тексты и один основной голубой акцент.

Главные принципы:

- игровое состояние важнее декора;
- цвет всегда сообщает смысл, а не просто украшает;
- панели отделяются границей и небольшим перепадом яркости, а не сильными тенями;
- свечение используется только для фокуса, выбранного объекта или важного действия;
- интерфейс должен одинаково хорошо читаться на поле боя и на экранах коллекции/магазина.

## 2. Цвета

Все токены объявлены в `src/assets/styles/main.css` через Tailwind `@theme`. В компонентах следует использовать семантические имена, а не произвольные hex-цвета.

| Токен            | Значение  | Tailwind-класс (пример)    | Назначение                          |
| ---------------- | --------- | -------------------------- | ----------------------------------- |
| `void`           | `#05070C` | `bg-void`                  | самая глубокая подложка, затемнение |
| `canvas`         | `#080B12` | `bg-canvas`                | основной фон приложения             |
| `surface`        | `#0E1420` | `bg-surface`               | панели, модальные окна              |
| `surface-raised` | `#151D2B` | `bg-surface-raised`        | карточки и элементы над панелью     |
| `surface-hover`  | `#1B2637` | `hover:bg-surface-hover`   | hover/активная строка               |
| `ink`            | `#F2F6FB` | `text-ink`                 | основной текст                      |
| `ink-muted`      | `#9AA9BC` | `text-ink-muted`           | подписи и вторичный текст           |
| `ink-faint`      | `#627086` | `text-ink-faint`           | неактивные данные, placeholder      |
| `line`           | `#243145` | `border-line`              | обычные границы                     |
| `line-strong`    | `#34465F` | `border-line-strong`       | выделенные границы                  |
| `accent`         | `#53D8FB` | `text-accent`, `bg-accent` | выбор, энергия, главное действие    |
| `accent-strong`  | `#16BDE9` | `hover:bg-accent-strong`   | hover основного действия            |
| `accent-soft`    | `#153849` | `bg-accent-soft`           | спокойная акцентная подложка        |
| `on-accent`      | `#031014` | `text-on-accent`           | текст поверх `accent`               |
| `success`        | `#55D6A8` | `text-success`             | восстановление, успех               |
| `warning`        | `#F4BF62` | `text-warning`             | кредит, предупреждение              |
| `danger`         | `#FF6B72` | `text-danger`              | урон, уничтожение, ошибка           |

Правило пропорций: примерно 80% экрана занимают фон и поверхности, 15% — текст и границы, не более 5% — акцентные и статусные цвета.

Не вводить отдельный цвет для каждой фракции, пока это не потребуется механике. Если фракционные цвета появятся, использовать их только на узкой полосе, эмблеме или бейдже карты; весь остальной каркас карты остаётся нейтральным.

## 3. Фон и поверхности

Глобальный фон уже задан для `body`: тёмная основа, мягкое голубое пятно сверху и редкий однопиксельный звёздный паттерн. Для основных экранов не нужно создавать ещё один полноэкранный градиент.

Уровни глубины:

1. `bg-canvas` — игровое поле и страницы.
2. `bg-surface border border-line` — сайдбары, верхняя панель, модальные окна.
3. `bg-surface-raised border border-line` — карты, строки списка, внутренние блоки.
4. `bg-surface-hover` — только краткое интерактивное состояние.

Прозрачность допустима для оверлеев: `bg-void/80 backdrop-blur-sm`. Не использовать blur на каждой панели — он ухудшает производительность и визуальную иерархию.

## 4. Типографика

Основной шрифт — системный sans-serif стек с приоритетом `Inter`, если он установлен. Это не создаёт внешнего сетевого запроса. Для крупных игровых заголовков доступен `font-display`, для числовых счётчиков — `font-mono` с `tabular-nums`.

- заголовок экрана: `font-display text-2xl font-semibold tracking-tight`;
- заголовок секции: `text-sm font-semibold uppercase tracking-[0.12em] text-ink-muted`;
- основной текст: `text-sm text-ink` или `text-ink-muted`;
- важный игровой показатель: `font-mono text-lg font-semibold tabular-nums`;
- микроподпись: `text-xs text-ink-muted`.

Не писать длинные строки целиком в uppercase. Его следует оставить для коротких HUD-подписей и категорий.

## 5. Геометрия и сетка

Базовый шаг отступов — 4 px (стандартная шкала Tailwind). Внутри компонентов чаще использовать `gap-2`, `gap-3`, `p-3`, `p-4`; между крупными секциями — `gap-6` или `gap-8`.

Скругления:

- контролы — `rounded-control` (10 px);
- панели — `rounded-panel` (14 px);
- игровые карты — `rounded-card` (16 px).

Карты должны сохранять единое соотношение сторон, рекомендуемое начальное значение — `aspect-[5/7]`. Минимальная удобная цель для нажатия — 44 × 44 px.

## 6. Тени, границы и свечение

- основная панель: `border border-line shadow-panel`;
- обычная карта: `border border-line`, без свечения;
- hover карты: `border-line-strong -translate-y-0.5`;
- выбранная карта: `border-accent shadow-glow`;
- недоступная карта: `opacity-50 saturate-50`, но текст должен оставаться читаемым.

Тень `shadow-glow` зарезервирована для выбранного объекта и primary-кнопки в особо важном контексте. Не совмещать несколько разноцветных свечений.

## 7. Состояния и анимация

Любое интерактивное состояние обозначается минимум двумя признаками: например, цветом границы и небольшим смещением. Нельзя полагаться только на цвет.

- hover: 150–200 ms;
- открытие панели/модального окна: 200–250 ms;
- перемещение карты: 250–400 ms;
- easing: `ease-out-expo`;
- масштаб на hover — максимум `scale-[1.02]`;
- постоянные пульсации допустимы только для события, которое ждёт решения игрока.

Глобально учтён `prefers-reduced-motion`: для таких пользователей анимации почти полностью отключаются.

## 8. Рецепты компонентов

### Основная кнопка

```html
<button
  class="rounded-control bg-accent px-4 py-2.5 text-sm font-semibold text-on-accent transition-colors duration-200 ease-out-expo hover:bg-accent-strong disabled:opacity-40"
>
  Завершить ход
</button>
```

### Вторичная кнопка

```html
<button
  class="rounded-control border border-line bg-surface-raised px-4 py-2.5 text-sm font-medium text-ink transition-colors duration-200 hover:border-line-strong hover:bg-surface-hover disabled:opacity-40"
>
  Отмена
</button>
```

### Панель

```html
<section class="rounded-panel border border-line bg-surface p-4 shadow-panel">
  <!-- содержимое -->
</section>
```

### Игровая карта

```html
<article
  class="aspect-[5/7] rounded-card border border-line bg-surface-raised p-3 transition duration-200 ease-out-expo hover:-translate-y-0.5 hover:border-line-strong"
>
  <!-- изображение, стоимость, название и свойства -->
</article>
```

У игровых карт должна быть стабильная структура: стоимость — в верхнем левом углу, название — рядом или сверху изображения, механика — в нижней части, основные показатели — по нижним углам. Так игрок быстрее сканирует ряд карт.

### Поле ввода

```html
<input
  class="w-full rounded-control border border-line bg-canvas px-3 py-2.5 text-sm text-ink placeholder:text-ink-faint hover:border-line-strong focus:border-accent focus:outline-none"
/>
```

## 9. Иконки, изображения и звук

Использовать один набор outline-иконок с толщиной линии около 1.5–2 px. Не смешивать outline, filled и эмодзи в одном интерфейсе. Иконка без подписи должна иметь `aria-label` или скрытый текст.

Арты карт могут быть насыщенными; интерфейс вокруг них намеренно остаётся нейтральным. Для читаемости текста поверх арта использовать локальный тёмный градиент, а не затемнять всю картинку.

Звуковые эффекты не должны дублировать каждое наведение. Звук уместен для подтверждения действия, покупки, получения урона и важных событий хода.

## 10. Доступность и адаптивность

- сохранять видимый `focus-visible` (глобальный стиль уже задан);
- для значимых текстов держать контраст не ниже WCAG AA;
- не передавать урон/успех только красным или зелёным — добавлять иконку, число или подпись;
- на мобильном устройстве переносить вторичные панели в drawer, а не сжимать поле;
- проверять интерфейс при ширине 320 px и при масштабировании текста до 200%;
- декоративные изображения должны иметь пустой `alt`, информативные — осмысленный `alt`.

## 11. Контроль перед добавлением компонента

1. Использует ли компонент существующие семантические цвета?
2. Понятны ли hover, focus, active, selected и disabled состояния?
3. Работает ли он без анимации и без распознавания цвета?
4. Совпадают ли отступы и скругления с общей шкалой?
5. Не конкурирует ли декор с игровой информацией?
6. Стабильна ли разметка при длинном тексте и крупных числах?

Новый токен стоит добавлять только тогда, когда одно и то же визуальное решение повторилось минимум в двух независимых компонентах.

## 12. Базовые UI-компоненты

Для форм следует использовать компоненты из `src/components/ui`, а не повторять наборы Tailwind-классов на каждой странице.

### `AppButton`

Поддерживает варианты `primary`, `secondary`, `danger`, `ghost` и размеры `sm`, `md`, `lg`. По умолчанию используются `variant="primary"`, `size="md"` и безопасный `type="button"`.

```vue
<AppButton type="submit">Сохранить</AppButton>
<AppButton variant="secondary" size="sm">Назад</AppButton>
<AppButton variant="danger" :loading="isDeleting">Удалить</AppButton>
```

Props `disabled`, `loading` и `block` отвечают за недоступное состояние, индикатор загрузки и ширину `100%`. Для иконок предусмотрены слоты `leading` и `trailing`.

Для навигации передавайте `to` (строку или объект маршрута) — компонент отрисует `RouterLink`. Для обычного адреса используйте `href`: будет создана ссылка `<a>`. Без этих props отрисовывается `<button>`; если переданы оба, приоритет у `to`.

```vue
<AppButton :to="{ name: 'games' }">Find a game</AppButton>
<AppButton to="/" variant="secondary">Return home</AppButton>
<AppButton href="https://example.com" target="_blank" rel="noopener noreferrer">Website</AppButton>
```

В режиме ссылки `disabled` и `loading` блокируют переход и обработчик `click`, убирают `href` и исключают элемент из Tab-навигации. Внешний вид и слоты одинаковы для кнопок и ссылок.

### `AppInput`

Компонент поддерживает `v-model`, props `label`, `hint`, `error`, `size`, `inputClass` и все стандартные атрибуты HTML input: `type`, `name`, `autocomplete`, `placeholder`, `disabled` и другие.

```vue
<AppInput
  v-model="login"
  class="mt-4"
  input-class="font-mono"
  label="Логин"
  name="login"
  autocomplete="username"
  :error="errors.login"
/>
```

Обычные `class` и `style` применяются к корневой обёртке компонента — через них задаются внешние отступы и ширина. `inputClass` предназначен для дополнительных классов нативного `<input>`.

`error` автоматически включает красную границу, `aria-invalid` и доступное сообщение об ошибке. Слоты `leading` и `trailing` позволяют добавить иконку или интерактивный контрол, например показ пароля.

### `AppSpinner`

Индикатор загрузки поддерживает размеры `sm`, `md`, `lg`. Внутри другого доступного контрола он используется без подписи как декоративный элемент. При самостоятельном использовании нужно передать `label`:

```vue
<AppSpinner size="lg" label="Загрузка игрового поля" />
```

### `StarfallLoader`

Фирменный loader для загрузки экрана или длительного процесса: орбитальные дуги, ядро звезды и световой след. Поддерживает размеры `sm`, `md`, `lg`, собственный `label` и скрытие видимой подписи через `:show-label="false"`. Даже скрытая подпись остаётся доступной для screen reader.

```vue
<StarfallLoader size="lg" label="Авторизация" />
```

Для небольших loading-состояний внутри кнопок и полей по-прежнему используется простой `AppSpinner`. `StarfallLoader` предназначен для центрального состояния целого экрана или крупной панели.

### `AppCard`

Базовая поверхность для самостоятельных смысловых блоков. Поддерживает HTML-тег через `as`, варианты `default`, `panel`, `raised`, `accent`, `danger`, отступы `none`, `sm`, `md`, `lg` и интерактивное состояние `interactive`.

```vue
<AppCard as="article" interactive>
  <!-- содержимое карточки -->
</AppCard>
```

`AppCard` следует использовать для карточек возможностей, форм-панелей, информационных блоков и CTA. Не нужно оборачивать им каждую группу элементов: таблицы без самостоятельного смысла, навигация и простые layout-контейнеры карточками не являются.

### `AppHeader`

Верхняя панель авторизованной части приложения. Слева всегда расположен знак и название Starfall, справа — действия пользователя. Панель имеет высоту 64 px, остаётся сверху при прокрутке и отделяется от содержимого тонкой границей. Основные игровые показатели в этот header добавлять не следует — для них нужен отдельный HUD игрового экрана.
